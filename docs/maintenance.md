# 維護說明

本文保留題庫更新與網站維護需要的規則。網站使用方式請看 [README](../README.md)，後端 API、儲存與部署設定請看 [投稿服務說明](../contribution-service/README.md)。

## 題庫內容

- 題目保留固定 ID；合併重複題時，保留來源版本、原有解析與舊 ID 對照，讓既有連結及待複習標記仍能對應。
- 來源有答案時設定 `answerProvided: true`；不要因缺圖、選項、解析或題意疑點重新標為待確認。未提供答案的題目保留待確認提示，文字題由讀者自行對照。
- 圖片題的文字題幹依原題轉錄，不改成摘要或自行加入條件；題圖中的程式碼不另抄進題幹。
- 解析需說明理由、計算步驟或適用條件。新來源只有簡短說明時，保留或補強既有完整推導。
- 修正答案時保留修正前答案與查核紀錄；不要自行宣稱沒有依據的「官方接受格式」。

## 雙語題目合併審核

- 題庫重複題只在題幹確認為同一題、完整選項逐項相同（可換序），且答案能按選項內容重新對應時合併。題意相近、共用選項或只有部分選項相同都保留為不同題。
- 合併題的畫面使用中文在上、英文在下；選項也依中文順序顯示，英文放在對應選項下方。保留題目固定 ID，舊題號作為別名，來源版本留在 `sourceVariants`。
- [2026-10-27 全庫雙語題目審核紀錄](../content/bilingual-question-audit-20261027.json)

## 批次比對與查重

批次查題每次最多 30 題、80,000 字；投稿每批最多 200 題。兩者用途不同，不應共用輸入上限。

比對需保留數學大小寫、比較方向、取整方式、題圖及填答要求。已核對的語言版本、選項換序與代號差異可對應同題；不能使用一般模糊拼字或忽略附加條件來套答案。

選擇題答案按貼上的選項內容重新對應。缺選項、答案衝突、缺少必要題圖或只有相似題時，應標為需確認。科目或單元選錯時提供切換提示，不把其他範圍已收錄的題目直接當作全站未收錄。

投稿同步失敗時，明示目前只比對內建題庫；不要以不完整資料宣稱全站未收錄。重新編輯或同步後必須再次比對，避免複製舊結果。

不能只因原有正確選項仍存在，就把改動過其他選項的新版本當成已確認答案；新的選項也可能變成正確答案。只接受完整選項集合一致、換序或已核對翻譯。內建索引先啟用，公開投稿在背景同步；同步有新資料時，既有結果必須標為過期。

## 修改與同步

以下命令均從專案根目錄執行。

作業系統題庫以 `os.html` 中的 `course-manifest` 與每單元 `data-course-unit` JSON 區塊保存。清單中的題數、題目 ID 與舊 ID 對照需和各單元資料一致；`scripts/course-data.mjs` 會在批次索引建置時讀取並驗證這些區塊。頁面只在需要時解析所選單元，全部單元搜尋會載入全部區塊。題庫仍內嵌在頁面中，以保留離線與本機開啟功能。

修改題庫、來源版本或選項對照後，更新批次索引及投稿查重資料：

```sh
node scripts/build-batch-library.mjs
node contribution-service/scripts/sync-library.mjs .
```

投稿前端有兩份檔案：根目錄的 `submit.html`、`review.html` 與 `assets/contributions-*.js`，以及 `contribution-service/frontend/` 的對應檔案。從根目錄修改後，使用上述同步器更新服務副本，並更新實際修改資源的版本參數。

根目錄前端與資料檢查：

```sh
npm test
```

投稿服務需先建置，再執行權限與資料流程檢查：

```sh
cd contribution-service
npm run build
npm test
```

單純修改批次頁排版不需發布投稿服務。修改題庫對照或投稿前端後，需同步、檢查並發布對應服務，避免網站查題與投稿查重的版本不同。

GitHub Pages 與 Sites 投稿服務分開發布；更新 GitHub 不代表 Sites 已更新。Sites 的來源、版本及發布流程見投稿服務說明。

`npm run test:all` 會依序執行前端檢查、投稿服務建置與服務測試。同步器會讀取目前題庫、已核對的來源版本與 `assets/batch-search-aliases.json`；`tests/submission-index.test.mjs` 驗證投稿索引涵蓋全部已核對選項語言組合，不能省略。

## 練習與待複習備份

兩科腳本依序載入 `question-tools.js`、作答判斷與課程 loader、`learning-tools.js`、`practice-progress.js`、`reading-flow.js`。進度模組使用課程 loader 的固定題目 ID；側欄預設展開、題目順序預設依題庫順序。重新開啟課程時從課程預設位置開始，不保存續讀位置。

待複習與閱讀字級保存在 `course-library.learning.v1.{course}`；本輪統計保存在 `course-library.practice.v1.{course}`。這些資料只在目前瀏覽器保存；作答原文不寫入網址，逐題作答欄位不跨重新整理保留。

待複習備份使用有版本與科目的 JSON；匯入先完整驗證，再合併寫入。錯誤科目、無效 ID、超量或儲存失敗必須保留原有清單；未同步的投稿 ID 可保留，舊 ID 透過合併對照遷移。

題庫答案呈現使用現有已核對的 `choiceKey` 或精確選項對應，顯示代號與內容；不能因改變顯示格式而改寫原始答案。資料缺漏提示和答案是否已提供分開處理，缺少來源選項時不得自行補造。

## 登入與資料保護

管理者日常使用帳號密碼登入；首次設定或忘記密碼依服務的管理者驗證流程處理。帳密與機密設定不得寫入前端、README 或 GitHub。

登入與設定表單明確使用 POST，等處理程式綁定後才啟用送出按鈕。避免改回瀏覽器預設的 GET，造成帳密出現在網址。

已發布題目可編輯、下架及還原，修改前版本保留紀錄。管理者的完整備份包含題圖連結，不包含圖片原始檔；不要把下載 JSON 當作已備份所有圖片。

本機草稿與收據依瀏覽器保存，清除瀏覽器資料會刪除；重要草稿請另行下載。

## 2026-10-25：練習與投稿改善

- 「開始新一輪練習」需確認後才會清除本輪統計及作答，待複習標記保留。
- 填空答案的替代寫法集中在 `assets/practice-feedback.js`，綁定科目、固定題號及未變動的標準答案；目前只收錄等待圖連字號及 `n!` 空格兩組核對過的表示法，不接受通用語意猜測。只有題幹有連續編號空格且答案有相同格數的 ` / ` 分隔時，才改用多格輸入。
- 完整學習備份使用 `course-library.full-learning` 第 1 版，涵蓋目前科目待複習標記、字級及本輪作答統計；不含輸入原文、續讀位置或投稿草稿。匯入先驗證全部內容，標記取聯集、同題練習採更新時間較新的一筆，重複匯入不累加次數。
- 各題「回報題目問題」免登入，回報綁定公開題目 ID，管理者在後台「題目勘誤審核」查看。確認需更正、已處理與不採納都需處理說明。確認勘誤不直接改寫答案：內建題另行更新主站，公開投稿可從既有題目管理編輯；回報內容與審核清單不公開。勘誤收據可查詢狀態與站主說明。
- 匯入投稿按 `course`、`unit` 分組；同組超過 200 題時拆批，一次最多 2,000 題及 20 批。缺少科目或單元時沿用所選範圍，無效的明示範圍會拒絕匯入。先展開分組預覽，再勾選同意並逐批送出。每批完成立即保存收據，重試使用固定 `clientRequestId` 避免重複新增；疑似重複題仍須另外確認。
- 分組草稿及收據使用 `course-library-grouped-submissions-v1`，與原手動新增草稿分開保存。分組下載檔可重新匯入；仍有未完成分組時，先下載並清空，才可匯入新檔。

## 單元測驗自訂範圍

測驗範圍可選目前單元、全部單元或連續的起始／結束單元（含兩端）。單元清單取自課程 loader 的 `examUnits()`，使用穩定單元 ID 篩選，不能從題目 ID 或顯示名稱猜測單元。OS 自訂範圍僅解析所選單元；測驗不改動閱讀單元及題庫篩選。起訖反向時不允許開始，範圍內的缺資料／無答案排除規則沿用既有測驗。開始前顯示可抽題數，開始後保留該次測驗的範圍標題。

## 未建立單元的投稿

投稿可選「投稿尚未建立的單元」，填 1–99 的章節編號及選填名稱。未知單元使用 `L<number>` 穩定 ID；編號若對應既有 OS 單元，會轉成原本的固定 ID，避免建立重複單元。`unitTitle` 隨草稿、分組投稿及審核保留；已知單元仍採原名稱。站主可在審核修改新單元名稱，核准前不公開。核准後 metadata 存在原有題目 JSON，不需要改動資料庫結構。

`GET /api/units?course=...` 只列出內建單元與仍有公開題目的投稿單元，不含待審核資料。課程頁依公開題目建立新單元導覽，批次查題也會加入新單元；單元測驗每次開啟設定時更新單元清單。內建題庫與原有固定 ID 保留。
