# 操作流程改善（2026-11-03）

狀態：本機修改與驗證完成，使用者已核准同步發布至 GitHub Pages 與投稿管理網站。正式題庫、題目答案、管理者權限及資料庫未變更。

## 已完成

1. 閱讀頁依目前單元顯示同步前後題數，分別計算新增、移除與更新。相同題數但答案或解析改變，也會顯示更新；無變更則明確標示。批次查題亦顯示全課程比對資料的同步差異。同步失敗時保留原資料並提供重試。
2. 從網站隨附的公開題庫快照產生獨立單元目錄。投稿與批次查題不必等待正式 API 才看得到 L9 記憶體管理；其他新增單元同步後會保存名稱快取，下一次可先顯示。挖寶仍在 L6 與 L7 之間。目錄僅包含名稱，不宣稱已同步最新題目。
3. 修正切換投稿模式會重新顯示空白預覽的問題。選檔前不顯示分組同意與送出區；解析成功或恢復既有草稿後才顯示。流程列標出選檔、核對或完成步驟。原有未送出草稿及收據保留。
4. 站內連結攜帶淺／深色偏好，到達目的頁後套用並記住，再清理外觀參數。保留單元、題目與錨點參數；不修改外站、下載及頁內跳轉連結。動態產生的站內連結亦處理。管理頁轉址與查題轉投稿也保留外觀。修正投稿服務的查題頁首連結，指向 GitHub Pages 的正式入口。
5. 兩科閱讀頁把「章節」篩選改稱「主題」，主題、題型與學習模式保持可見；次要題目狀態收進預設關閉的「更多篩選」。桌面／手機切換不會自動打開該區。啟用狀態篩選後顯示「已啟用」及可移除的篩選標記；深色搜尋圖示加強對比。

- 瀏覽器確認空白投稿、既有草稿恢復、L9 目錄、深色工具列、次要篩選啟用與重設。桌面 1365、手機 390 像素寬度下檢查；手機內容寬度與捲動寬度同為 375，無橫向溢出。

## 後續可重用流程

新增或更新網站隨附單元時：

```powershell
node scripts/build-unit-catalog.mjs
node scripts/prepare-flow-clarity-20261103.mjs
node contribution-service/scripts/build.mjs
```

相關測試：

```powershell
node --experimental-vm-modules --test tests/flow-clarity.test.mjs tests/submission-inbox.test.mjs tests/workflow-improvements.test.mjs tests/grouped-submissions.test.mjs tests/batch-loading.test.mjs tests/course-exam.test.mjs tests/option-randomization.test.mjs contribution-service/tests/permissions.test.mjs
```

驗證紀錄位於工作區 `verification/flow-clarity-tests.txt` 與 `verification/flow-clarity-build.txt`，截圖位於 `verification/flow-clarity-20261103/`。

外觀一致適用於透過站內連結切換；兩個不同網域不會共用 localStorage，也沒有跨裝置同步。第一次看到其他人剛建立、尚未收進快照的新單元，仍須等待網路確認一次。

發布時必須一起更新 GitHub Pages 與既有 Sites 投稿服務。僅推送 GitHub 不會更新服務；不要覆蓋服務專有樣式、重新產生題目身分或改寫正式資料庫。
