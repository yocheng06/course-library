# 管理安全與備份（2026-11-18）

## 管理登入

管理頁「管理工具 → 帳號安全」可啟用 TOTP 第二道驗證。輸入目前密碼後，站主自行在手機驗證器手動加入金鑰，再以六位驗證碼確認；完成確認前不改變登入要求。支援 RFC 6238 SHA-1、六位數、30 秒週期及前後一個週期的時鐘誤差。同一驗證碼不可重複使用。

啟用時產生八組高熵備援碼，只顯示一次；每組只能使用一次，登入仍需要密碼。備援碼只保存雜湊，手機金鑰以 AES-GCM 加密保存，使用伺服器既有 `RATE_HASH_KEY` 秘密衍生加密金鑰。**啟用後不要直接更換或遺失此秘密**；如需輪替，先由擁有者規劃重新設定驗證器。不要把金鑰、備援碼或完整 SQL 備份提交 GitHub。

所有安全設定都檢查管理員 session；啟用／停用與登出其他裝置會變更安全版本，使舊 session 失效。停用需要目前密碼與新的驗證碼或未使用備援碼。帳密登入及敏感操作保留 IP 嘗試限制。session 簽章另結合伺服器秘密；僅取得資料庫中的密碼雜湊不足以偽造 cookie。

一般登出也會在伺服器記錄撤銷的 token 雜湊，複製的同一 token 不能繼續使用。cookie 維持 Secure、HttpOnly、SameSite=Strict，最長八小時。這次簽章升級會讓既有管理登入失效，需要重新登入一次。

若手機遺失，使用密碼及備援碼登入，再重新設定驗證器。若手機與所有備援碼都遺失，必須由 Cloudflare 帳戶擁有者在控制台執行經驗證的復原；網站沒有免驗證的公開重設入口。Cloudflare 帳戶本身的雙重驗證須由站主另外啟用。

## 網頁防護

全部服務回應加入 CSP：腳本限本站，不允許行內腳本或 `eval`；禁止外站嵌入、外部表單提交與 `<base>` 改寫。樣式保留必要行內設定，題圖仍可使用 HTTPS、data 與 blob。另設定 HSTS、nosniff、Referrer-Policy，並關閉不需要的相機、麥克風、定位、付款與 USB 權限。

這些措施不改動任何人可新增、修改及可復原移除公開題目的共享規則，也不能保證阻止惡意內容編輯。修改歷史與定期備份仍必要。

## 備份與復原

已實際取得 D1 Time Travel 復原點。此功能由 Cloudflare 自動維護，不需額外開啟或建立排程，保留範圍依方案；見 [官方說明](https://developers.cloudflare.com/d1/reference/time-travel/)。不啟用 R2 訂閱。

本次變更前另以官方 Wrangler 匯出完整 SQL 到本機忽略目錄，包含 D1 題圖與管理資料；以獨立 SQLite 還原、檢查完整性與資料表題數。網站原有「完整備份（含題圖）」仍可匯出不含管理密碼的備份 JSON，並核對 SHA-256。正式復原應先在獨立環境驗證，不能把舊 SQL 直接重匯入目前的正式資料庫。

完整 SQL 備份比公開題庫敏感，須離線安全保存；D1 同帳戶的自動復原不能取代另外保存的備份。備份檔案、實際復原點與私密資料不放入公開 Repository。

## 驗證

後端測試涵蓋 RFC 測試向量、逾時設定、來源及登入限制、TOTP 與備援碼防重放、並行兌換、舊 session 撤銷、停用條件及安全標頭。前端測試檢查備援碼下載格式、離開頁面清除敏感內容，以及延遲回應不會重新顯示設定金鑰。正式啟用驗證器需站主本人完成。
