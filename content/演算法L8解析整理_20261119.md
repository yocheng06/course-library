# 演算法 L8 解析整理

## 集合與實作比較｜多選題

陣列實作 vs 指標實作，下列敘述正確的是？

- 指標實作無需記憶體
- 陣列實作空間固定
- 陣列實作存取快
- 指標實作插入彈性好

答案：B、C、D

在本題的固定容量陣列與動態鏈結模型中，陣列空間先決定，可用索引快速取得指定位置；指標實作則可逐個配置節點，插入位置已知時只需調整連結。

例如在陣列中間插入要搬移後方元素，串列可把新節點接入。指標本身及節點都占記憶體，不能說不需要空間。陣列也可另外做動態擴容，但那是額外管理機制，不代表普通固定陣列自動增長。

## 集合與實作比較｜多選題

下列哪些結構是動態的？

- 鏈結串列
- 靜態陣列
- 堆疊
- 佇列

答案：A、C、D

動態結構／動態集合可在執行中透過插入、刪除改變元素數量。鏈結串列能按需配置節點；堆疊與佇列也能隨 push／pop、enqueue／dequeue 改變內容，因此本題將它們列為動態結構。

但「元素個數會變」不等於「底層容量無上限」：陣列堆疊仍可能固定容量，鏈結版也受可用記憶體限制。靜態陣列的配置大小固定；若額外做成可擴容容器，是另一種實作。串列填空填 dynamic。

## 集合與實作比較｜多選題

下列哪些是動態集合（Dynamic Set）操作？

- INSERT
- SEARCH
- SORT
- DELETE

答案：A、B、D

Dynamic set 的基本操作可包含 search、insert 與 delete：搜尋鍵值、加入元素、移除元素；查詢本身不必改變集合，但仍屬集合介面的一部分。

例如先 search 找到鍵值 7，再 delete 移除它，或 insert 新鍵值 9。Sort 是重新整理元素順序的演算法，並非每個動態集合都需要提供的基本操作；尤其集合的抽象意義本來就不一定要求某種儲存順序。

## 堆疊｜單選題

當堆疊已滿時再進行 push 操作，會發生什麼？

- 溢位 (Overflow)
- 下溢 (Underflow)
- 正常執行
- 自動擴展

答案：A

Overflow（溢位）是容量已滿，卻還要放入新元素。以固定容量為 3 的堆疊為例，依序 push 10、20、30 後，再 push 40 就無位置可寫，應回報 overflow。

Underflow 是空堆疊還要取出元素，方向相反。這裡採固定容量陣列模型，不會正常寫出陣列界限，也不保證自動擴展；可擴容的實作必須另有配置與搬移機制。填空填 overflow。

## 堆疊｜單選題

當堆疊為空時再進行 pop 操作，會發生什麼？

- 溢位 (Overflow)
- 正常執行
- 無反應
- 下溢 (Underflow)

答案：D

Underflow（下溢）是堆疊已空，卻仍執行 pop。因為沒有頂端元素可回傳，操作必須依介面規定回報錯誤，而非正常取出資料。

例如依序 push 5、pop 得到 5，此時再 pop 就下溢。Overflow 則是已滿還要加入，不能混用；「沒有反應」也沒有正確表達這個非法操作。填空填 underflow。

## 堆疊｜單選題

堆疊（Stack）資料結構遵循哪種原則？

- 隨機存取
- 優先級最高先出
- 先進先出 (FIFO)
- 後進先出 (LIFO)

答案：D

堆疊遵循 LIFO：Last In, First Out，後進先出。像把盤子一個個疊上去，最後放上的盤子位於頂端，也最先拿走。

依序 push 10、20、30，連續 pop 會得到 30、20、10。FIFO 是佇列規則，依優先級取出屬優先佇列；隨機存取不是堆疊的抽象操作。陣列可以拿來實作堆疊，但「陣列」本身不強制使用 LIFO。填空填 lifo。

## 堆疊｜單選題

堆疊的 top 指標通常初始值設定為？

- 設定為 NULL
- 設定為 1
- 設定為 -1
- 設定為 0

答案：D

本題採用從 1 開始存放元素的堆疊模型：top 表示目前元素數／頂端索引，空時設為 0。第一次 push 先把 top 加到 1，再寫入 stack[1]。

如果改用從 0 開始、top 指向最後一個已使用位置的模型，空時常設為 −1；鏈結實作也可能用 NULL 表示空。它們都是不同約定，不能跨模型混用。此題選 0，要和本單元「先增加 top 再寫入」的偽碼一起理解。

## 堆疊｜單選題

在堆疊中，刪除操作通常稱為？

- push
- dequeue
- enqueue
- pop

答案：D

刪除並取出堆疊頂端元素的操作叫 pop；加入頂端叫 push。佇列則使用 enqueue 加入、dequeue 移除。

例如堆疊由底至頂是 4、7、9，pop 回傳 9，剩下 4、7。要先確認堆疊非空，再更新 top，避免 underflow。Pop 不需要搜尋整個堆疊，也不是刪除任意位置的元素。填空填 pop。

## 堆疊｜多選題

在陣列實作的堆疊中，需要維護的資訊有？

- 每個節點的指標
- 陣列最大容量
- top 指標
- 陣列內容

答案：B、C、D

陣列堆疊需保存陣列內容、最大容量與 top。陣列保存元素，top 指出頂端／目前使用量，容量用來檢查是否還有空間。

例如容量 5、top = 2，表示本模型用了前兩格，下一次 push 寫第 3 格；top = 5 就不能繼續放入。陣列元素已能透過索引定位，不需要每個元素再保存 next／prev 指標；那是鏈結節點的組織方式。

## 堆疊｜多選題

堆疊支援的基本操作包含？

- PUSH
- STACK-EMPTY
- POP
- SEARCH

答案：A、B、C

Push 加入頂端元素，pop 取出頂端元素，stack-empty 檢查是否為空，都是堆疊的基本介面。

例如先以 stack-empty 確認狀態，再決定能否 pop。Search 雖然可以另外掃描底層陣列或鏈結節點來實作，但不是 LIFO 堆疊規定的基本操作；不能因此把「可以寫出來」與「標準基本介面」視為相同。

## 堆疊｜多選題

關於 PUSH 操作，下列何者正確？

- 檢查 overflow
- 檢查 underflow
- 增加 top 指標
- 將值放入 stack[top]

答案：A、C、D

固定容量陣列的 push 要先檢查 overflow，再增加 top，最後把新值放入 stack[top]。

例如原 top = 2、加入 8，先確認仍有容量，再令 top = 3，寫 stack[3] = 8。Underflow 是 pop 前檢查的空堆疊問題，不能拿來判斷是否還能加入。順序也不能顛倒，否則可能覆寫原頂端或使用錯誤索引。

## 堆疊｜填空題

PUSH(S, x)
1 top[S] <- top[S] + 1
2  ____________  <- x

POP(S)
1 if STACK-EMPTY(S)
2     then error "underflow"
3     else top[S] <- top[S] - 1
4          return  ____________

答案：S[top[S]]/S[top[S]+1]

第一空填 S[top[S]]；第二空填 S[top[S]+1]。依題目逐行追蹤 top 的變化，不能只記 pop 一定回傳哪個寫法。

Push：原 top = 2，第一行變成 3，因此第二行要寫 S[3]，即 S[top[S]]。

Pop：若原 top = 3 且 S[3] = 9，第三行已先把 top 減成 2，所以回傳原頂端時要讀 S[2+1]，即 S[top[S]+1]。若寫 S[top[S]] 就會誤讀下一層。空堆疊先回報 underflow，不進入這段更新。

## 佇列｜單選題

下列哪種結構支援 FIFO？

- 二元樹
- 堆疊
- 佇列
- 陣列

答案：C

## 佇列｜單選題

佇列的 head 指標通常指向？

- 最後一個插入的元素
- 下一個將被移除的元素
- 隊伍中間的元素
- NULL

答案：B

Head 通常標示佇列前端，也就是下一個要被 dequeue 移除的元素。Tail 則標示加入端；精確是否指向下一個空格，須看實作約定。

例如依序加入 6、8、9，head 指向 6，先移除 6 再前進到 8。最後加入的 9 不是下一個服務對象，中間位置也不是 FIFO 的移除端；只有某些鏈結空佇列的 head 才會是 NULL。

- dequeue
- pop
- push

答案：A

答案：A、C、D

## 鏈結串列基礎｜單選題

鏈結串列相比陣列的優勢為？

- 隨機存取速度快
- 插入與刪除彈性較大
- 記憶體連續
- 無需儲存指標

答案：B

鏈結串列的插入與刪除可透過修改鄰接連結完成，不必像一般陣列在中間插入時搬移後續所有元素，因此結構調整較有彈性。

例如已知相鄰節點 a、b，要在中間加入 x，只需令 a.next = x、x.next = b。前提是已找到操作位置；搜尋位置仍可能花 O(n)。串列不要求連續記憶體，但需要儲存連結；隨機取得第 i 個元素通常較慢，不能像陣列直接用索引定位。

## 鏈結串列基礎｜單選題

鏈結串列（Linked List）的節點通常包含什麼？

- 僅指標
- 鍵值與指標
- 整數陣列
- 僅鍵值

答案：B

節點通常同時包含資料與連結：key 保存鍵值，next 指向後繼節點；雙向串列另外有 prev 指向前驅。

例如節點的 key = 12、next 指向下一個節點，才能既保留資料又把節點接成清單。只有鍵值無法知道下一個在哪，只有指標則沒有保存此節點的鍵值。Length 通常是整張清單的管理資訊，不是每個節點的必要欄位。填空的關鍵字域填 key；prev 選項以本單元雙向節點模型理解。

## 鏈結串列基礎｜單選題

如果一個鏈結串列的 head 為 NULL，代表？

- 該清單已滿
- 該清單為空
- 該清單為環狀
- 該清單只有一個元素

答案：B

在沒有哨兵節點的普通鏈結串列中，head 指向第一個資料節點；head = NULL 表示連第一個節點都不存在，所以清單為空。

只有一個節點時，head 仍須指向它；是否已滿和配置資源有關，不能從 NULL 推得；環狀串列也會有可指向的節點。若實作採固定哨兵，空表可能是 head 指向哨兵，需先確認使用哪一種模型。

## 鏈結串列基礎｜多選題

鏈結串列的常見變體有？

- 單向鏈結串列
- 佇列
- 環狀鏈結串列
- 雙向鏈結串列

答案：A、C、D

單向、雙向與環狀是鏈結串列常見的組織變體，分別著重連結方向與尾端是否回接起點。雙向與環狀還可以結合成雙向環狀串列。

## 鏈結串列操作｜多選題

下列哪些操作會改變鏈結串列的結構？

- INSERT
- SEARCH
- DELETE
- TRAVERSE

答案：A、C

Insert 會增加節點並改接連結，delete 會把節點移出並接回前後節點，因此兩者改變清單結構。

例如 a → b 插入 x 後成 a → x → b；刪 x 又回到 a → b。普通 search 只比較鍵值尋找目標，traverse 只沿連結走訪，兩者不會因此改變節點之間的關係。這裡指標準唯讀查找／遍歷，不包含另行設計的自我調整串列。

## 鏈結串列操作｜多選題

在雙向鏈結串列中，刪除節點 x 需要？

- prev[next[x]] = prev[x]
- 更新指標
- 移動資料
- next[prev[x]] = next[x]

答案：A、B、D

刪除雙向串列中的 x，要讓前驅與後繼互相連接：next[prev[x]] = next[x]，以及 prev[next[x]] = prev[x]。兩個方向都必須更新。

例如 a ↔ x ↔ b，第一個指定相當於 a.next = b，第二個相當於 b.prev = a。若 x 在表頭，要改 head；若 x 在表尾，後繼為 NIL，不能對 NIL 寫 prev。一般不需搬動其餘節點資料。偽碼兩空依序填 next[prev[x]]／prev[x]；若先呼叫 LIST_SEARCH，查找 O(n) 也要另計。

- 可以在 tail 插入
- 可以在中間插入
- 不需要指標移動

- 是否為環狀結構

普通鏈結串列無法直接用索引跳到任意位置，搜尋時須由 head 依 next 逐個比較，所以是 linear（線性）遍歷，最壞 O(n)，主要隨清單長度增加。
