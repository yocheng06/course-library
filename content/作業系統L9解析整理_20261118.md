## 記憶體保護｜單選題

哪個暫存器用於在連續記憶體分配中標記程序的起始物理地址？

- 基底暫存器 (Base Register)
- 索引暫存器 (Index Register)
- 限制暫存器 (Limit Register)
- 程式計數器 (Program Counter)

答案：A

Base register（基底暫存器）保存程序所在區域的起始實體位址。合法邏輯位址通過界限檢查後，會與 base 相加。

例如起點 2000、邏輯位址 80，實體位址為 2080。Limit register 保存的是可用長度；index register 協助索引運算；program counter 指向接下來要執行的指令，都不是本題問的區域起點。

- Base and Limit Register
- PC and Instruction Register
- Index and Stack Pointer
- Page and Segment Register

答案：A

## 記憶體保護｜多選題

哪些是記憶體保護 (Protection of Memory) 的目標？

- 提高 CPU 的時脈速度
- 確保程式執行的正確性
- 確保使用者程序之間互不影響
- 確保作業系統不受使用者程序影響

答案：B、C、D

記憶體保護像替各程序劃出可使用的房間：一個程序不能任意修改其他程序或核心的資料。它能防止越界寫入破壞執行結果，支援程序之間隔離，也保護作業系統。

因此「程序互不影響」「作業系統不受使用者程序影響」及「確保程式正確運作」符合目標。這裡的正確運作指防止非法記憶體存取干擾，並不保證程式沒有邏輯錯誤；提高 CPU 時脈則與此保護機制無關。

## 記憶體保護｜多選題

In memory protection, which conditions are jointly checked using the Base Register and Limit Register?

- Logical address < Base Register
- Logical address < Limit Register
- Logical address ≤ Limit Register
- Logical address ≥ 0

答案：B、D

先檢查邏輯位址，再加上基底：合法條件是 0 ≤ logical address < limit，通過後 physical address = base + logical address。

例如 limit = 100，從 0 起算只有 0～99 共 100 個位置，所以等於 limit 已越界，不能使用 ≤ limit。Base 是實體起點，不能拿邏輯位址是否小於 base 來判定合法；負位址也不在此範圍內。

## 位址繫結｜單選題

Load Time address binding typically requires the compiler to generate which type of code?

- Static Code
- Absolute Code
- Virtual Code
- Relocatable Code

答案：D

載入時才知道程式要放在哪個實體起點，因此編譯器必須先產生 relocatable code（可重定位程式碼）。載入器確定起點後，才能調整需要重定位的位址。

例如程式內某資料位於起點後 40 位元組，載入到 1000 時對應 1040，改載到 3000 時則是 3040。Absolute code 已固定位置，不適合這種需求；static／dynamic 描述其他特性，virtual code 也不是這組繫結階段使用的標準對應名稱。填空填 relocatable。

## 位址繫結｜多選題

載入時間 (Load Time) 地址綁定具有哪些特性？

- 不需要 MMU 的硬體支持
- 程式在執行時可以被移動
- 程式的最終物理地址在載入時確定
- 編譯器產生可重定位程式碼

答案：A、C、D

載入時繫結的流程是：編譯器先留下可重定位位址 → 載入器選定實體起點 → 修正位址並開始執行。因此「產生可重定位程式碼」「最後實體位址在載入時確定」成立。

單就這種繫結而言，不必靠 MMU 在每次存取時重新定位；這不代表整個作業系統沒有 MMU 或不需要任何保護硬體。若執行中還要任意搬移，須採執行時繫結，因此「執行時可搬移」不屬此階段特性。

## 位址繫結｜多選題

執行時地址綁定 (Execution Time Address Binding) 具有哪些特性？

- 程式碼必須是可重定位的
- 地址轉換由 MMU 處理
- 允許程序在執行期間移動
- 生成絕對程式碼

答案：A、B、C

執行時繫結把邏輯位址到實體位址的轉換交給 MMU，在存取當下依目前映射決定位置。程序可在執行期間搬移，位址映射與程式內容也必須允許重定位。

可想成程式一直使用同一組房間編號，由管理員更新它實際對應哪棟樓。「MMU 處理轉換」「允許搬移」「可重定位」符合此模型；生成固定實體位址的 absolute code 則與這種彈性相衝突。

## 架構案例：ARM／Intel｜多選題

關於 Intel x86-64 架構的分頁，哪些敘述是正確的？

- 使用四級分頁層次結構
- 實際僅實作 48 位元地址空間
- 頁面大小包括 4 KB, 2 MB, 和 1 GB
- 不支持頁地址擴展 (PAE)

答案：A、B、C

以四級 x86-64 分頁與 4 KB 頁面計算：每級索引 9 位，共 4 × 9 = 36 位；頁內偏移 12 位，所以線性位址轉譯合計 36 + 12 = 48 位。常見映射大小包括 4 KB、2 MB 與 1 GB；長模式分頁需要啟用 PAE，不能選不支援 PAE。

48 是此四級模型的答案，不等於 x86-64 永遠只能使用 48 位；支援五級分頁的系統可用 57 位線性位址。虛擬位址寬度與實體位址寬度也應分開。填空填 48。

## 架構案例：ARM／Intel｜填空題

允許 32 位元應用程式存取超過 4GB 物理記憶體空間的 Intel 技術是 ____________ 。 (請用小寫英文回答)

答案：pae

PAE 擴大的是可使用的實體位址範圍。32 位元位址共有 2^32 bytes，也就是 4 GiB；支援 PAE 的系統可用較寬的實體位址管理超過此容量的 RAM。

這不會讓每個 32 位元程序自動得到超過 4 GiB 的線性位址空間，單一程序要使用更多資料仍須配合作業系統提供的映射方式。Dynamic loading 是按需載入，inverted page table 是表結構，address binding 是建立位址對應，都不是這項實體位址擴充技術。填空填 pae。
