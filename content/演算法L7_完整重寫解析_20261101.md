## L7-2468｜順序統計量與中位數｜單選題

一個集合的第 i 個順序統計量（ith order statistic）是指該集合中第幾個小的元素？

本題答案：A

解題思路與過程
把數字由小到大排列後，第 i 個就是第 i 小。這裡的「第幾個」指大小排名，不是原陣列的位置。
例如原資料 [9,2,7,4]，排序後是 [2,4,7,9]。i＝3 的答案是 7；原陣列第 3 格剛好也是 7 只是巧合，換個排列仍要得到同一答案。

逐一看選項
A. 第 i 小的元素
A 是定義本身：排序後數第 i 個。

B. 第 i 大的元素
第 i 大由大往小數；本例第 3 大是 4，與第 3 小不同。

C. 中位數
中位數只對應中間順位，不能代表任意 i。

D. 平均數
平均數要將數字加總再除以個數，甚至不一定是集合中的元素。

## L7-2472｜順序統計量與中位數｜單選題

本題答案：A

A. 第 n/2 個順序統計量

B. 最小值
最小值是第 1 小，通常不在中央。

C. 最大值
最大值是第 n 小，通常不在中央。

D. 總和
總和是把所有值相加，沒有找中央位置。

## L7-2498｜順序統計量與中位數｜多選題

取第 n/2+1＝4 小，是上中位數 9。

偶數情況仍可定義中位數，只需說明採哪個慣例。

## L7-2499｜順序統計量與中位數｜多選題

順序統計量演算法常見複雜度？

本題答案：A、B、C

這題比較的是不同解法與不同情況，不是說同一次執行同時具有三種緊確複雜度。

極端分割的隨機選擇會退化成平方時間。

D. O(1)
任意未排序資料一般不能只看固定幾格就找到指定順位；已排序後讀一格才是 O(1)。

## L7-2501｜順序統計量與中位數｜多選題

先排序再取第 i 個，的確是一種解法。

## L7-2469｜最小值與最大值｜單選題

尋找集合中最小值（Minimum）的基本演算法時間複雜度為？

本題答案：A

解題思路與過程
先拿第一個數當目前最小值，再依序檢查剩下 n−1 個。
例：[8,3,5,1]：min＝8；比 3 後變 3；比 5 後仍為 3；比 1 後變 1。共 3＝n−1 次比較，因此時間隨 n 線性成長。

逐一看選項
A. O(n)
基本掃描是 Θ(n)，所以選 O(n)。

B. O(log n)
沒有排序等額外資訊時，不能每次砍掉一半資料。

C. O(n log n)
O(n log n) 是寬鬆上界，但題目問基本演算法的代表性成長率；緊確答案是線性，不需先排序。

D. O(1)
未查看的元素可能更小，不能只做固定次數的工作。

## L7-2470｜最小值與最大值｜單選題

要在一個有 n 個元素的集合中同時找到最小值與最大值，最有效率的比較次數大約為？

本題答案：A

解題思路與過程
關鍵是每兩個數共用一次比較。先比較這對數，較小者只需挑戰 min，較大者只需挑戰 max：一對兩個元素只要 3 次。
例 n＝6：第一對 [8,3] 比 1 次建立 min＝3、max＝8；第二對 [5,1] 比 3 次；第三對 [9,4] 再比 3 次。合計 7＝3×6/2−2，而分別掃描要 10 次。
偶數 n 的精確式為 1+3(n−2)/2＝3n/2−2；奇數 n 為 3(n−1)/2。題目問「大約」，取主項 1.5n。

逐一看選項
A. 1.5n
兩個元素共用 3 次比較，主項是 3n/2。

B. 2n
約 2n 是分別找最小與最大，未利用配對省比較。

C. n
一般 n 下只約 n 次不足以同時確認兩個極值；特殊小 n 不代表一般公式。

D. n log n
完整排序會做更多工作，不是這裡最佳比較次數。

## L7-2483｜最小值與最大值｜單選題

若以兩兩比較的方式，尋找最小值需要進行幾次比較？

本題答案：A

解題思路與過程
每一次大小比較，最多淘汰一個「可能是最小值」的候選者。從 n 個候選者淘汰到剩 1 個，至少需要 n−1 次。
直接掃描也剛好做到 n−1 次，因此既必要又足夠。例 n＝4，只要依序用目前最小值與另外三個數比較，共 3 次。

逐一看選項
A. n-1
n−1 剛好把 n 個候選縮成 1 個。

B. n
第一個元素用來初始化，不需再多算一次比較。

C. n/2
只配對一次會留下約 n/2 個勝者，還沒決定最小值。

D. 1
只有 n＝2 才剛好一次；一般 n 不成立。

## L7-2488｜最小值與最大值｜多選題

尋找最小值與最大值的優化方法包含？

本題答案：A、B

解題思路與過程
目標只有兩個極值，不必把全部數排好。直接掃描可一路維護 min、max；配對法再利用「較小者不可能是最大、較大者不可能是最小」節省比較。
例如 n＝6，分別掃描要 2n−2＝10 次，配對法只要 3n/2−2＝7 次。兩者時間都是 Θ(n)，但比較次數不同。

逐一看選項
A. 配對比較法
配對後每兩個新元素只用 3 次比較，是本章的改善方法。

B. 直接掃描
直接掃描是線性、常數輔助空間的基本有效方法；不代表比較數也等於配對法。

C. 使用堆積
堆積可用於其他選擇需求，但本題從原始陣列找兩個極值不必另建堆，也未因此獲得本章的比較數優勢。

D. 先排序
先排序能求極值，卻多做了中間所有排名的工作，不是此題要的優化。

## L7-2494｜最小值與最大值｜多選題

比較次數分析中，同時尋找最大值與最小值的好處？

本題答案：A、B

解題思路與過程
各自找最小、最大要 (n−1)+(n−1)＝2n−2 次比較。配對後先分出每對大小，只讓較小者競爭 min、較大者競爭 max，偶數 n 改為 3n/2−2。
例如 n＝100：各自掃描 198 次；配對 148 次，少了 50 次。兩者仍都是線性時間，改善的是比較數與常數成本。

逐一看選項
A. 減少總比較次數
共用每對的第一次比較，總數確實減少。

B. 提升效率
在比較有成本的模型下，少比較能降低工作量。

C. 簡化程式邏輯
配對需要奇偶初始化與分支，程式不一定更簡單。

D. 減少記憶體使用

⑤ 140 是本題設定的固定門檻，小於它就直接處理；固定大小的成本可包成 O(1)。例如 n＝200，兩個遞迴規模上界為 40 與 146，加上本層線性工作。精確證明需處理取整與 +6，不能把 9/10 當成忽略常數後就完成的全部證明。

## L7-2513｜確定性 Select 與中位數的中位數｜填空題

假定有 n 個數 (以下的 A B C D .... 都是數值) 考慮以下的 Median of Medians 問題 若根據課本的的演算法 各組已排序 且找到中位數也以排序 若以下的 M 為中間值 請問 比M大的 節點數 會大於多少 (不用 CEILING 與 FLOOR) ____________ A ... B C D ... E F ... G H I ... J K ... L_M_N ... O P ... Q R S ... T U ... V W X

本題答案：3n/10-6

解題思路與過程
填 3n/10-6。它是「至少能保證多少個比 M 大」的保守下界，不是每次恰好有這麼多個。
① 每組五個，排序為 a<b<c<d<e，組中位數是 c。若 c>M，那麼 c、d、e 三個都一定比 M 大；a、b 是否大於 M 則無法保證。
② 共約 n/5 組，M 是組中位數的中位數，所以約一半組的中位數在 M 的大側。每個這類組至少貢獻 3 個，主項是 (n/5)×(1/2)×3＝3n/10。
③ 嚴格計數不能直接把每組都算滿：最後一組可能不足五個，M 自己所在組也要排除。用保守估計扣掉最多兩組的三元素貢獻，得到 3(n/10−2)＝3n/10−6；取整細節由教材的保守界吸收。
④ n＝200 時，保證下界為 60−6＝54 個，實際可能更多。較小側也有對稱保證，所以繼續找答案的那側至多約 200−54＝146 個。
讀原圖時只沿「同組已排序」及「組中位數已排序」推大小；不同組的任意兩個非中位數不能只靠圖上的左右位置就認定大小。上述嚴格 > 關係採本章元素互異假設。

## L7-2522｜確定性 Select 與中位數的中位數｜填空題

為了保證線性時間， median order 裡面的Select 演算法將元素分成＿＿＿組

本題答案：five

解題思路與過程
填 five，應讀成「每組五個元素」，不是「全體只分成五組」。
例：n＝23 時，分成 5、5、5、5、3 個，共 ⌈23/5⌉＝5 組；n＝100 時則是 20 組，每組仍為 5 個。
五個排好 a<b<c<d<e，組中位數 c 兩邊各有兩個。若 c>M，連同 c 至少三個一定比 M 大，因而能推出約 3n/10 的同側保證。
組數量級是 n/5，選 pivot 與目標側的主要遞迴比例合計 1/5+7/10＝9/10<1，所以能證最壞線性時間。five 是本題採用的分組大小，不是宣稱其他組大小都不可能線性。
